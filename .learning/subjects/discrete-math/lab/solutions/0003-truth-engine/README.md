## 它做了哪七件事

| 任务 | 落在哪个函数 | 关键点一句话 |
| --- | --- | --- |
| 1 · 穷举赋值 | `valuations` | `itertools.product` 让最后一个变元变得最快，正好是「第一个变元占最高位」 |
| 1 · 编号 | `index_of` | 从头往下读，`index = index * 2 + 这一位`；位序反了整张 Σm 表一起错位 |
| 2 · 求值 | `evaluate` | 蕴含只有「前真后假」为 0；用 `min`/`max` 顶替会悄悄算成合取/析取 |
| 3 · Σm 编号 | `minterms` | 真值列的下标就是编号，只挑值为 1 的下标；`maxterms` 是补集 |
| 4 · 反例 | `counterexamples` | 前提全真 **且** 结论为假，两个条件缺一不可 |
| 4 · 有效性 | `is_valid` | 反例为空 ⇔ 有效；变元取前提与结论的并集 |
| 5 · 对账 | `mismatches` | 返回 `(编号, 引擎说, 答案说)`；答案表漏掉一题也算对不上 |

## 十六道题：十一道有效、五道无效

`cases.py` 里 `C02`–`C10` 是课件 1.8 的例题（直接证法、附加前提法、归谬法、分情况证明各有着落），
`C01` 是 1.8.2 真值表法那道最小样板，`C14` 是前提自相矛盾的那一格。

无效的五道，反例都能一眼验出来：

| 编号 | 错法 | 反例 | 逐格验 |
| --- | --- | --- | --- |
| `C11` | 肯定后件 `P→Q, Q ⇒ P` | `01` | 前提 $1$、$1$ 全真，结论 $P=0$ —— 推理无效 |
| `C12` | 否定前件 `P→Q, ¬P ⇒ ¬Q` | `01` | $\neg P$ 真、$P\to Q$ 真，而 $\neg Q$ 假 |
| `C13` | 充分当必要 `P→Q ⇒ Q→P` | `01` | 前件真，结论 $Q\to P$ 在 $Q=1,P=0$ 上为假 |
| `C15` | 至少一支当唯一 `P∨Q, P ⇒ ¬Q` | `11` | 两前提都真，$\neg Q$ 假 |
| `C16` | 结论当前件 `P∧Q→R, R ⇒ P∧Q` | `001`、`011`、`101` | $R=1$ 使前提全真，而 $P\wedge Q=0$ |

`C14` 要注意：前提是 $P$ 与 $\neg P$，没有一个赋值能让前提全真，所以反例为零、判**有效**。
有效说的是「不存在前提真而结论假的赋值」，它不保证结论本身为真——这正是定义 1.8.2
「相容 / 不相容」那一段的意思，也和你纸上写归谬法时「推出矛盾就说明原推理有效」是同一件事。

`C09` 有七个变元（$P,Q,R,S,T,U,W$），穷举 128 个赋值。手算时「$\neg R$ 与 $P\wedge Q\to R\wedge S$」
一撞就出结果，程序则是老老实实把 128 行走完——这正是它值得写的原因：手算只判过一题，
剩下几十道全靠它一次验完。

## 第 1 步 · 穷举赋值与编号

**这一小步在讲什么。** 真值表法之所以能「判定」，靠的是变元有限：$n$ 个变元只有 $2^n$ 种赋值，
一种一种试过去，没有遗漏就没有争议。程序里这一步是 `itertools.product`，一行就完；
难的是**顺序**——返回的第几项必须正好是第几号赋值，否则后面所有编号一起错位。

编号规则与第 1 课那张表一模一样：变元按字母顺序排，**第一个变元占最高位**，真记 1。
所以 $P=1$、$Q=0$、$R=1$ 的编号是 $101_2=5$，记 $m_5$。

**现在做。** 填两个函数：

- `valuations(variables)`：返回全部赋值的 dict 列表，下标即编号。

  | 调用 | 返回 |
  | --- | --- |
  | `valuations(['P', 'Q'])` | `[{'P':0,'Q':0}, {'P':0,'Q':1}, {'P':1,'Q':0}, {'P':1,'Q':1}]` |
  | `valuations(['P'])` | `[{'P':0}, {'P':1}]` |

- `index_of(env, variables)`：一个赋值的编号（整数）。

  | 调用 | 返回 | 因为 |
  | --- | --- | --- |
  | `index_of({'P':1,'Q':0}, ['P','Q'])` | `2` | $10_2=2$ |
  | `index_of({'P':1,'Q':0,'R':1}, ['P','Q','R'])` | `5` | $101_2=5$ |
  | `index_of({'A':0,'B':0,'C':1,'D':1}, ['A','B','C','D'])` | `3` | $0011_2=3$ |

**要点。**

- `itertools.product((0, 1), repeat=3)` 生成 `(0,0,0) (0,0,1) …`：**最后一个**变元变得最快，
  正好就是「第一个变元占最高位」。别自己反转一遍，反转过的顺序照样「像」对的。
- `zip(variables, bits)` 把一位一位贴回变元名；写成 `dict(...)` 就是一条赋值。
- `index_of` 用「从头往下读，`index = index * 2 + 这一位`」，不要用 `2 ** 位置` 硬算——
  指数写错一位是同一个毛病，而且看不出来。

1. `valuations(['P','Q','R'])[5]` 应当是哪个赋值？（提示：$101_2$）
2. 三个变元时，`index_of` 里 $P$ 乘的是几？$R$ 乘的是几？

## 第 2 步 · 递归求值

**这一小步在讲什么。** 公式是嵌套元组，求值就是照结构递归：变元查表，`not` 取反，
`and` 取小、`or` 取大，`imp` 单独算。四种联结词里**只有蕴含不对称**，所以它最容易写错。

**现在做。** 填 `evaluate(formula, env)`，返回 `0` 或 `1`：

| 公式 | 赋值 | 真值 | 这一格在验什么 |
| --- | --- | --- | --- |
| `('imp','P','Q')` | $P=1,Q=0$ | 0 | 蕴含唯一为假的情形 |
| `('imp','P','Q')` | $P=0,Q=0$ | 1 | 前件假，整个蕴含真 |
| `('imp','P','Q')` | $P=1,Q=1$ | 1 | 后件真 |
| `('and','P',('not','Q'))` | $P=1,Q=0$ | 1 | 否定号嵌在式子里 |
| `('imp',('imp','P','Q'),'R')` | $P=1,Q=1,R=0$ | 0 | 前件本身是蕴含 |

**要点。**

- 变元那一支是 `return env[formula]`，`formula` 是字符串时就是变元。
- `not` 只有一支被否定：`1 - evaluate(formula[1], env)`。若写成 `1 - evaluate` 整式，嵌套时立刻错。
- 蕴含写成「前件为 0 **或** 后件为 1 时为 1」，别用 `min` / `max` 顶替——
  那会把 $P\to Q$ 算成合取或析取，而真值表仍然「有 0 有 1」，错得不显眼。

**卡在这里就问自己两句。**

1. $P=0$、$Q=0$ 时 $P\to Q$ 是几？为什么「前件假」时整个蕴含算真？
2. `('and','P','Q')` 与 `('imp','P','Q')` 在 $P=1,Q=0$ 这一行分别是几？哪一行能区分这两个联结词？

**怎么算过。** `python -m unittest -v test_engine.TestEvaluate`

## 第 3 步 · 真值列 → Σm 编号

**这一小步在讲什么。** 第 1 课在纸上做的那张真值表，程序里就是一条 0/1 列表：
第 $i$ 项是 $i$ 号赋值上的真值。主析取范式的编号 $\Sigma m$ 就是「值为 1 的那些下标」，
主合取范式的编号 $\Pi M$ 就是补集——两条编号合起来正好占满 $0\ldots 2^n-1$。

**现在做。** 填 `minterms(formula, variables)`，返回升序的整数列表：

| 公式 | 变元 | Σm | 说明 |
| --- | --- | --- | --- |
| `('imp','P','Q')` | `['P','Q']` | `[0, 1, 3]` | 只有 10 那一行是假 |
| `('and','P','Q')` | `['P','Q','R']` | `[6, 7]` | $R$ 取什么都不影响 |
| `('or','P',('not','P'))` | `['P']` | `[0, 1]` | 重言式：占满全部编号 |
| `('and','P',('not','P'))` | `['P','Q']` | `[]` | 矛盾式：一个都没有，记作 $0$ |

`truth_values` 与 `maxterms` 已经写好了（`truth_values` 就是拿 `valuations` 套 `evaluate`，
`maxterms` 是取补集），你只填 `minterms`。

**要点。**

- `enumerate(truth_values(...))` 的下标就是编号，所以这一步一个变元都不用算——只看列表。
- 返回升序：`enumerate` 天然按下标走，别 `sorted` 也别 `set` 后乱序返回。
- 「重言式占满全部编号、矛盾式是空表」这两条是第 1 课的类型判定，现在由断言替你验。

**卡在这里就问自己两句。**

1. `('and','P','Q')` 在三个变元时为什么是 `[6, 7]`？$R=0$ 与 $R=1$ 各对应哪个编号？
2. 断言报 `Σm 编号不对` 时，先看它给的列表与你手算差在哪几个数——差的是同一行，还是从头错位？

**怎么算过。** `python -m unittest -v test_engine.TestMinterms`

## 第 4 步 · 反例与有效性

**这一小步在讲什么。** 这是整节的核心。定义 1.8.1 说：$C$ 是前提 $H_1,\dots,H_n$ 的有效结论，
当且仅当 $H_1\wedge\cdots\wedge H_n\to C$ 是重言式。落到赋值上就是一句话：

> **反例 = 一个让「前提全真、结论为假」的赋值。**
> 反例一个都没有，推理有效；有一个，就无效，那个赋值就是依据。

两个条件缺一不可。只判「结论为假」会把「前提本来就不成立」的赋值也算成反例，于是每题都无效；
只判「前提全真」又会把结论为真的赋值也算进去。这一步写错，16 道题的判定会成片地反。

**现在做。** 填两个函数：

- `counterexamples(premises, conclusion, variables)`：返回反例的 dict 列表，按编号从小到大；
  没有反例返回 `[]`。

  | 前提 | 结论 | 反例 |
  | --- | --- | --- |
  | `[('imp','P','Q'), 'Q']` | `'P'` | `[{'P':0,'Q':1}]` |
  | `[('or','P','Q')]` | `('and','P','Q')` | `[{'P':0,'Q':1}, {'P':1,'Q':0}]` |
  | `['P', ('not','P')]` | `'Q'` | `[]`（前提永远不真，没有反例） |

- `is_valid(premises, conclusion)`：返回 `True`/`False`。变元取「前提与结论里出现过的全部变元」的
  并集（`variables_of` 已经给你了），不能各按自己出现的算——结论里没出现的变元，前提的每一行都要穷举到。

**要点。**

- 一行 `if all(...) and evaluate(conclusion, env) == 0` 就是全部逻辑，别拆成两趟循环。
- 两个条件里最容易漏的是 `all(...)`：只写 `evaluate(conclusion, env) == 0` 时，
  `C11`（肯定后件）与 `C14`（前提矛盾）的判定会一起反掉，`TestValidity` 会连着报。
- 「无效」不等于「结论是假的」。无效只说明**存在**一个赋值让结论落空；结论在别的赋值上照样可以为真。
  所以报依据时要说清是哪个赋值，而不是说「结论错了」。
- 前提自己矛盾时（`C14`），反例为零，判定为**有效**——这叫空洞有效，定义 1.8.2 的相容/不相容讲的就是这一格。

**卡在这里就问自己两句。**

1. `[('imp','P','Q'), 'Q']` 与结论 `'P'`，哪一行赋值让两个前提都真而 $P$ 假？
2. 你的 `counterexamples` 在 `C14` 上返回了 4 项而不是 0 项，漏掉了哪个条件？

**怎么算过。** `python -m unittest -v test_engine.TestValidity`

## 第 5 步 · 与纸上答案对账

**这一小步在讲什么。** 八道推理题你在纸上写过证明，基本都对。这一节要验的是同一批题的另一面：
**判定**。两边必须对得上——纸上写得出证明的，引擎要判有效；引擎判无效的，那张纸上其实写不出证明，
你该在纸边上补一个反例赋值。

**现在做。**

1. 填 `engine.mismatches(case_list, answers)`：返回 `(编号, 引擎说, 答案说)` 三元组列表，
   按题库顺序；答案表里没有的编号也算对不上（`答案说` 那一项是 `None`），否则漏填一题会静默通过。
2. 填 `audit.py` 的 `MY_ANSWERS`：把题库这 16 道**逐题在纸上判一遍**再填。
   纸上有过的那几道照纸上抄，没写过的当场判。然后

   ```sh
   python audit.py
   ```

   第一轮（引擎 vs 课件）应当打出「对不上 0 道」；第二轮（引擎 vs 你纸上）也应当是 0 道。

**要点。**

- 对账不是「让程序替我判」，是先判再对：顺序倒过来，错的只是格式，看不出你哪一题判反了。
- 第二轮报出来的那几道，先回去**复算反例**（用 `report.py` 打出来的那个赋值逐行验一遍前提）。
  若反例确实存在，你纸上那份「证明」一定在某一行偷偷用了结论——这是 1.8 里最隐蔽的一处。
- `mismatches` 要按题库顺序返回，别用 `set`：对账表要能一眼看出错在哪一行。

## 加练（可选，两三分钟）

拿第 1 课那道作业题验一下「有效 ⇔ 前提合取蕴含结论是重言式」：

```python
import engine
p = [('imp', 'P', 'Q'), ('imp', 'Q', 'R')]
print(engine.is_valid(p, ('imp', 'P', 'R')))                       # True
print(engine.minterms(engine.entailment_formula(p, ('imp','P','R')),
                      ['P', 'Q', 'R']))                            # [0..7] 全部
q = [('imp', 'P', 'Q'), 'Q']
print(engine.minterms(engine.entailment_formula(q, 'P'), ['P', 'Q']))  # 缺 1，正是反例
```

第二条打印出来是一串缺一个号的编号：缺的那一号就是反例。判有效与求主析取范式，
在这里是同一件事的两种说法。

## 第 1 步 · 依据栏拆成三段

**这一小步在讲什么。** 考试答卷上最容易被扣的就是依据栏。它其实只有四种写法：`P`、
`P（附加前提）`、`T，行号，规则名`、`T，附加前提行号，行号，CP`。程序要把这一行字符串拆成
「规则、引了哪几行、规则名」三段，才谈得上逐行核。**拆不出来本身就是一种错**，所以认不出时
返回 `None`，让后面的检查报「第几行的依据栏认不出」，而不是当场抛异常。

**现在做。** 填 `proof.py` 的 `parse_basis(basis)`，返回 `(规则, 行号元组, 规则名)`：

| 依据栏 | 拆成 |
| --- | --- |
| `P` | `('P', (), '')` |
| `P（附加前提）` | `('P+', (), '')` |
| `T，2，3，拒取式` | `('T', (2, 3), '拒取式')` |
| `T，2，7，CP` | `('CP', (2, 7), 'CP')` |
| `T，拒取式` | `('T', (), '拒取式')` |
| 认不出（`前提`、空串） | `None` |

**要点。**

- 先按逗号切段：第一段是 `P` 还是 `T`，决定这是哪一类依据。
- 段里是数字的进行号，不是数字的是规则名；`CP` 单独成类。
- 行号从 1 数，和答卷一致。别在这步就把行号减一——减一是查表时候的事。

**卡在这里就问自己两句。**

1. `'T，2，3，拒取式'` 切完是几段？哪几段是数字？
2. `'T，CP'` 拆出来行号是空元组，这算拆错了吗？（不算——依据写漏了，是第 3 步要报的事。）

**怎么算过。** `python -m unittest -v test_proof.TestBasis`

## 第 2 步 · 七条蕴含式：看到什么形状写哪一条

**这一小步在讲什么。** 依据栏写了规则名还不够，规则名得跟这一行推出来的公式配得上。
本节的七条蕴含式是整行引用的：它们只负责把手里已有的几行拼成新的一行，
没有一条能改公式内部（那是等值式的事）。

**现在做。** 填 `is_step(name, refs, conclusion)`：`refs` 是引用那几行的公式（顺序无关），
`conclusion` 是这一行想写的公式。支持下面七条，认不出的 `name` 一律返回 `False`。

| 规则名 | 手里要有什么 | 这一行写什么 |
| --- | --- | --- |
| 假言推理 | `P→Q` 与 `P` | `Q` |
| 拒取式 | `P→Q` 与 `¬Q` | `¬P` |
| 析取三段论 | `P∨Q` 与 `¬P` | `Q`（反过来也对：`¬Q` 得 `P`） |
| 假言三段论 | `P→Q` 与 `Q→R` | `P→R` |
| 化简 | `P∧Q` | `P`（或 `Q`） |
| 合成 | `P` 与 `Q` | `P∧Q` |
| 附加 | `P` | `P∨Q`（凑出一支就够） |

**要点。**

- 这一步**跟行号无关**：只判形状。行号对不对是第 3 步的事，两件事分开写才查得准。
- `refs` 是列表，顺序不固定，别按下标取；用「在不在里面」判断。
- 拒取式最容易只认前一半：有 `P→Q` 还要有 `¬Q`，少一半就推不出 `¬P`。
- 合成与化简是反过来的两条：一条拆合取，一条拼合取。混了就写出「由 `P` 得 `P∧Q`」。

**卡在这里就问自己两句。**

1. 手里有 `P→Q` 和 `Q`，能不能写 `¬P`？缺的是哪一行？
2. 手里有 `P∨Q` 和 `¬P`，结论写 `Q` 走的是哪条规则？写 `P` 又为什么不行？

**怎么算过。** `python -m unittest -v test_proof.TestStep`

## 第 3 步 · 逐行体检：先形状、再行号、最后规则

**这一小步在讲什么。** 阅卷人拿到答卷是逐行往下看的，程序也一样：一行里先看依据栏写得
认不认得出，再看引的行存不存在（引用后面还没写出来的行＝抄错行号），再看这一步在蕴含式上
成不成立。**一行只报一条**，报完就换下一行——报一串重复的错反而看不见真正的问题。

**现在做。** 填 `line_issues(lines)`，返回问题清单（字符串列表，没问题就是空列表）。
判断顺序固定，报错句子照 `proof.py` 里那五句原话（断言比的是整句）：

| 这一行的毛病 | 报哪一句 |
| --- | --- |
| 依据栏认不出 | `第 %d 行：依据栏「%s」认不出——…` |
| T 行没写行号 | `第 %d 行：依据栏「%s」没写行号——…` |
| 引了还没出现的行 | `第 %d 行：引用了第 %s 行，那一行还没出现` |
| 规则名不在七条里 | `第 %d 行：规则名「%s」不在本节这七条里` |
| 这一步推不出 | `第 %d 行：第 %s 行按「%s」推不出 %s` |
| CP 行行号不足两个 | `第 %d 行：CP 的依据要写两个行号——…` |

**要点。**

- P 行与「P（附加前提）」行不引行号，直接放过（它们的合法性在第 4 步判）。
- 「引了未来的行」与「引了第 0 行」是同一类：行号必须落在 `1 … 本行行号-1` 里。
- 查表取公式时行号要减一：答卷从 1 数，列表从 0 数。这一处最容易差一位。
- CP 行这一步合不合法**不在这里判**，交给第 4 步——它的依据是两个行号，不是一条蕴含式。

**卡在这里就问自己两句。**

1. 第 4 行写着 `T，5，拒取式`，这算什么错？该报哪一句？
2. 第 4 行的 `P→Q` 存在第 2 行，`cited` 里它是第几项？

**怎么算过。** `python -m unittest -v test_proof.TestLines`

## 第 4 步 · 收口：CP 要还原，归谬要推成矛盾

**这一小步在讲什么。** 逐行都对，整份仍可能废——废在第一行和最后一行。
四条路线只在首末两行上有区别（中间都是 P 与 T）：

| 路线 | 首行 | 末行 |
| --- | --- | --- |
| 直接证法 | 前提逐条写 `P` | 结论本身 |
| 附加前提法 | 前件写 `P（附加前提）` | 前件→被证出者，依据带 `CP` 与两个行号 |
| 归谬法 | 结论的否定写 `P（附加前提）` | 一对矛盾，另起一句「按归谬法」 |

**现在做。** 填三个函数：

- `is_contradiction(f)`：`A∧¬A` 这种形状算一对矛盾，左右顺序不限。
- `ending_issues(proof)`：核「结论有没有被当前提」「CP 有没有还原」「归谬有没有推成矛盾」，
  报错句子照 `proof.py` 里那几句原话。判断按下面四条路分头走：
  - 有 CP 行 → 核末行是不是「附加前提 → 前一行」、依据栏的两个行号对不对、末行是不是结论；
  - 有附加前提行、没有 CP 行，且末行是矛盾（或 `closing` 里写了「归谬」）→ 核假设是不是结论的否定、
    末行是不是一对矛盾、有没有那句「按归谬法」；
  - 有附加前提行、没有 CP 行，且不是归谬 → 就是「没还原」；
  - 都没有 → 直接证法，末行必须等于结论。
- `check_proof(proof)`：把 `line_issues` 与 `ending_issues` 拼起来；一行都没有的证明，
  返回 `['一行都没有：先把前提逐条写成 P 行']`。

**要点。**

- 「结论的否定」有现成的 `negate`：`¬P` 的否定是 `P`，别写成 `¬¬P`。
- CP 末行的两个行号是**第一个行号＝附加前提那一行**，第二个是凑出后件的那一行，
  顺序反了阅卷人也扣。
- 归谬的末行不写结论，写矛盾。所以「末行是不是结论」这条只对直接证法与 CP 成立。
- 附加前提行请进来只借不还，是本题最常见的废卷方式：中间全对，末行停在 $R$。

**卡在这里就问自己两句。**

1. 末行是 `R`、附加前提是第 2 行的 `S`、结论是 `S→R`，这算哪条路线的错？
2. 末行是 `R∧¬R`、`closing` 是空串，报哪一句？

**怎么算过。** `python -m unittest -v test_proof.TestEnding`

## 第 5 步 · 六份标本，再录一份自己的

**这一小步在讲什么。** `proof_broken.py` 是六份**能拆、但过不了某项检查**的答卷，六处正是
作业里丢分的地方。断言把「每份该报哪一句」钉死，你以后见同样的错法就能自己认出来。

**先别改标本。** 先跑

```sh
python -m unittest -v test_proof.TestBroken
```

再对着六份标本读下表：

| 标本 | 错在哪 | 断言报的那一句 |
| --- | --- | --- |
| `S1_NO_NUMBERS` | 第 4 行只写 `T，拒取式` | 没写行号 |
| `S2_CP_NOT_RESTORED` | 推到 `R` 就交卷 | 附加前提没有还原 |
| `S3_WRONG_ASSUMPTION` | 归谬第 1 行写成 `¬P` | 假设应当是结论的否定；且第 3 行跟着推不动 |
| `S4_NO_CLOSING` | 矛盾后面没那句说明 | 缺一句「按归谬法」 |
| `S5_GOAL_AS_PREMISE` | 第 4 行把结论当 `P` 行 | 循环论证 |
| `S6_INCOMPLETE` | 末行停在 `¬Q` | 末行不是结论 |

`S3` 会一次报两句：假设写错之后，后面的推导跟着塌，第一处塌在第 3 行。
这不是断言太吵，而是真实答卷的样子——**假设错，整串错**。

**现在做：录一份自己的。** 拿课件 1.8.3 例4——前提
`(P→(Q∨R))∧(¬S→¬Q)∧(P∧¬S)`，结论 `R`——先在三列表上写完整证明，再录进 `proof.py` 末尾的
`MY_PROOF['lines']`（结论 `'R'` 已经写好了，别改）：

```python
MY_PROOF = {
    'goal': 'R',
    'lines': [
        (('and', 'P', ('not', 'S')), 'P'),
        # ……照你的答卷往下录
    ],
    'closing': '',
}
```

录完再跑一次全量测试：`check_proof(MY_PROOF)` 要交回空清单。

**要点。**

- 先手写、再录。倒过来做，错的就只是格式，看不出推导缺哪一步。
- 每一行问自己两件事：我引了哪几行？按哪条规则？两样都写进依据栏。
- 报错会说「第几行按某条推不出某某」，照行号回去看那一行的两支对不对。

**卡在这里就问自己两句。**

1. 前提里有 `P∧¬S`，要往上接 `P→(Q∨R)` 与 `¬S→¬Q`，第一步该拆哪一边？
2. `Q∨R` 与 `¬Q` 凑出 `R`，依据栏写哪一条规则？
